# Lesson 2.2 — Hard rules vs style preferences

**Module:** Instructions that stick  
**Duration:** ~6–8 min teaching + ~4–8 min interactive

## Learning objective

Mark safety and compliance as hard rules; keep tone and formatting as soft preferences that can flex.

## Teaching

### Beat 1

Hard rules: never send, never invent policy, always escalate P1, cite knowledge when quoting numbers.

### Beat 2

Soft preferences: concise bullets, calm tone, prefer tables for comparisons.

### Beat 3

When hard and soft conflict, hard wins. Write that explicitly so the model does not 'be nice' by breaking a rail.

### Talk-over narration (instructor VO)

*(Beat 1)*  
“At Acme Ops, assistants only work when teammates trust them. This lesson locks that trust.”

*(Beat 2)*  
“Stay model-agnostic: the same pattern applies whether you ship a Custom GPT, a Project, or a Gem.”

*(Beat 3)*  
“You’re done when you can apply this on a fictional Acme Ops workflow without guessing.”

## Worked micro-example

**Before**

> Be helpful and friendly and also never guess.

**After**

> HARD: If the answer is not in knowledge, say 'Unknown — escalate to ops lead' (do not invent). SOFT: Prefer calm, short bullets for standup.
