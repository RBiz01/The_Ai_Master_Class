# Lesson 5.1 — Versioning assistants like products

**Module:** Versioning, evals & iteration  
**Duration:** ~6–8 min teaching + ~4–8 min interactive  
**Interactive:** `l01-interactive.html`

---

## Learning objective

Label assistant versions (v1.2), owners, and changelog entries so teammates know what changed.

## Lesson video

![Lesson video](assets/l01-video.mp4)

**Video:** `assets/l01-video.mp4` — example/theme clip for this lesson.

## Teaching

### Beat 1

Put version in the name or description: Acme Ops Vendor Triage v1.2.

### Beat 2

Changelog: what changed, why, risk, owner. Keep it in a short knowledge file or team doc.

### Beat 3

Never silently overwrite a team-shared assistant on a Friday afternoon.

### Talk-over narration (instructor VO)

*(Beat 1)*  
“At Acme Ops, assistants only work when teammates trust them. This lesson locks that trust.”

*(Beat 2)*  
“Stay model-agnostic: the same pattern applies whether you ship a Custom GPT, a Project, or a Gem.”

*(Beat 3)*  
“You’re done when you can apply this on a fictional Acme Ops workflow without guessing.”

## Worked micro-example

**Before**

> Edit live instructions whenever inspiration hits.

**After**

> Branch: draft v1.3 offline → eval golden set → publish → changelog: 'stricter Unknown escalate phrase'.

Apply this lesson on a fictional **Acme Ops** assistant before Monday—then version what you ship.
