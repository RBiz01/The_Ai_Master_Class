# Lesson 3.4 — Privacy & least-privilege packs

**Module:** Files, knowledge & boundaries  
**Duration:** ~6–8 min teaching + ~4–8 min interactive  
**Interactive:** `l04-interactive.html`

---

## Learning objective

Build knowledge packs with least privilege: no secrets, no real PII, scoped docs per assistant.

![Lesson video](assets/l04-video.mp4)

**Video:** `assets/l04-video.mp4` — example/theme clip for this lesson.

## Teaching

### Beat 1

Classroom and production rule: fictionalize examples; never upload credentials, PANs, or private HR files.

### Beat 2

Prefer a thin SOP extract over dumping the whole shared drive.

### Beat 3

Separate assistants for HR vs vendors so knowledge does not cross domains.

### Talk-over narration (instructor VO)

*(Beat 1)*  
“At Acme Ops, assistants only work when teammates trust them. This lesson locks that trust.”

*(Beat 2)*  
“Stay model-agnostic: the same pattern applies whether you ship a Custom GPT, a Project, or a Gem.”

*(Beat 3)*  
“You’re done when you can apply this on a fictional Acme Ops workflow without guessing.”

## Worked micro-example

**Before**

> One Mega Assistant with HR reviews, vendor contracts, and API keys in a zip.

**After**

> Vendor Triage pack: public SLA + fictional playbook only. HR stays in a private HR Coach with tighter sharing.
