# Lesson 3.2 — Freshness, versioning & stale docs

**Module:** Files, knowledge & boundaries  
**Duration:** ~6–8 min teaching + ~4–8 min interactive  
**Interactive:** `l02-interactive.html`

---

## Learning objective

Label knowledge with versions and review dates; remove stale files that fight the current policy.

## What to do

1. Cue up the **Lesson video** and watch it once before you dig into the text.
2. Read **Teaching** carefully — especially the worked example you can reuse Monday.
3. Open `l02-interactive.html` and follow its Instructions until you hit the success state (this locks in: Freshness, versioning & stale docs).
4. Apply the idea once in your words (sticky note or note app is fine).
5. **You’re done when:** you can explain — in plain language — *Label knowledge with versions and review dates; remove stale files that fight the current policy.* and `l02-interactive.html` shows success.

## Teaching

### Beat 1

Two conflicting PDFs = random answers. One current file beats five 'maybe useful' uploads.

### Beat 2

Filename pattern: AcmeOps_Portal_Runbook_v4_2026-08-01.md with owner and review date in the header.

### Beat 3

Quarterly knowledge hygiene is part of owning the assistant.

### Talk-over narration (instructor VO)

*(Beat 1)*  
“At Acme Ops, assistants only work when teammates trust them. This lesson locks that trust.”

*(Beat 2)*  
“Stay model-agnostic: the same pattern applies whether you ship a Custom GPT, a Project, or a Gem.”

*(Beat 3)*  
“You’re done when you can apply this on a fictional Acme Ops workflow without guessing.”
